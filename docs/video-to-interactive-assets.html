1. 为什么这件事现在很急迫

机器人需要"在仿真里犯错一百万次,才能在现实里不犯错一次"。但仿真器里没有那么多螺丝钉。

具身智能(embodied AI)在 2025-2026 年迎来一个非常具体的瓶颈:训练数据不够。 大型视觉-语言-动作模型(VLA,如 π₀、π₀.₅、Helix、GR00T N1、G0)需要海量"机器人做某件事"的数据——但现实中由人类遥操作收集的数据成本极高(每小时数千美元),且数据多样性受限。

Figure AI 2025 年 11 月公布的数据很有代表性:在 BMW 斯帕坦堡工厂部署的 Figure 02 机器人累计跑了 1,250+ 小时,装载了 90,000+ 个钣金件,执行了 1,200,000+ 机器人步 [Ref-1]。这已经是行业里规模数一数二的真实数据——但若想训练下一代基础模型,需要的是 1000 倍以上。

核心思路 → 仿真合成。如果在仿真器里能"凭空"生成一批几何精确、物理可信的工业资产(螺丝钉、连接件、扳手),并且这些资产能被机器人抓取、被装配、被碰撞——那么训练数据就可以无限扩增。这就是"可交互资产"(Interactive Asset)的本质。

传统的"3D 扫描 → 网格简化 → 物理引擎导入"管线流程长、单价贵($50-$500/件)、且生成的网格往往没有铰接关节、没有可标注的物理参数。能不能用一段手机拍的视频,几秒钟就还原出可被机器人使用的资产?这是 2026 年整个领域押注的方向。

本文档的判断(结论先说)

  1. 2026 年最有希望的工程路径是 "VLM 做语义路由 + 专用模型做几何/物理"(详见 §3.5)
  2. 学术与工业的两套典范已经出现:OVOW(单物体 → URDF)与 SimFoundry(场景 → OmniGibson/Isaac Lab)
  3. 国内光轮智能(Lightwheel AI)是该方向的数据基础设施上游,应优先合作而非自建
  4. 传统 CAD 厂商的 Text2CAD 路线仍处早期(MUSE 基准 19-21% 通过率),不应作为主路线
  5. 纯世界模型(Astra / Genie 3)仍是 2D 像素输出,不能直接用于机器人训练

2. 第一性原理:什么是"可交互资产"

"可交互"在机器人语境里 = 物理可操作性(physics-enabled operability)。一个看起来很炫的 3D 网格,如果不能被仿真器里的机器人抓取、不能和环境发生接触碰撞,那只是"3D 资产",不是"可交互资产"。

2.1 几何层:从像素到物理表示

一段视频 = 一串 RGB 帧 $I_1, I_2, ..., I_T$。我们想要的是重建出物体在物理仿真引擎里能被表述的状态。最常见的有四种表示:

显式网格(Mesh)

顶点+面片:
$\mathcal{M} = \{v_i \in \mathbb{R}^3\}_{i=1}^{N_v}, \{f_j\}_{j=1}^{N_f}$

✓ 渲染快,与 PhysX/MuJoCo 兼容
✗ 拓扑变化时难优化

隐式场(Neural Field)

神经网络拟合密度场:
$F_\theta(x,y,z) = \sigma \in [0,1]$

✓ 拓扑自由,适合稀疏视角
✗ 需 marching cubes 提取表面,慢

高斯泼溅(3DGS)

百万个 3D 高斯点:
$g_k = \{\mu_k, \Sigma_k, c_k, \alpha_k\}$

✓ 新视角渲染 SOTA,训练快
✗ 非真网格,接触碰撞难

O-Voxel(2025 新)

稀疏体素+神经场:
$O = \{o_i = (x_i, F_i)\}$

支持开放表面、非流形。代表:TRELLIS.2(详见 §3.5)。

2.2 物理层:从外观到动力学

为了让机器人在仿真里能"操作"这个资产,引擎需要的物理参数至少包括:

$$ \text{Physics}(\text{asset}) = \{m, \mu_s, \mu_k, E, \nu, \text{joints}\} $$

其中 $m$ = 质量、$\mu_s / \mu_k$ = 静/动摩擦系数、$E$ = 杨氏模量、$\nu$ = 泊松比、joints = 关节定义。

这是当前最大的难点:从一段视频里同时估计出这些物理量,几乎不可能——你看到的只是"外观"。 当前主流做法是用 LLM(ChatGPT-5.x、Claude Opus 4.7、Gemini 3.x)从物体类别推断材质属性,然后在仿真器里机械臂试探(tactile probing)做精确标定。

2.3 交互层:让仿真器能"操作"

最后,资产必须被导出为仿真器能识别的格式:

  • URDF — ROS 生态,刚体+关节树
  • MJCF — MuJoCo,支持软体
  • USD / USDZ — NVIDIA Omniverse / Isaac Sim,工业标准
  • glTF / GLB — Web 友好,PBR 纹理、轻量
信息瓶颈:视频 → 资产的信息流压缩比是 3600:1(2-5 分钟 × 30 fps 视频 ≈ 数十 MB 像素,产出 ≈ 数百 KB 网格 + 几个标量)。中间必有信息压缩 + 语义抽象。这一观察贯穿全文,是 §3.5 "VLM 路由 + 专用模型"的理论根据。

3.1 路线一:2D 像素视频世界模型(Astra / Veo / Cosmos)

把视频生成模型(Sora、Veo 3、Cosmos、Astra)反过来用——不是"生成新视频",而是"理解一段视频后推测物体在 3D 空间里的样子"。直观理解:看到一段旋转的螺丝刀,虽然只看到几个角度,但模型会自动"脑补"它背面长什么样。

澄清:Astra(Tsinghua + Kuaishou, ICLR 2026, arXiv:2512.08931)本质是 2D 像素视频生成,基于 Wan2.1-1.3B 视频 DiT 冻结 backbone 的自回归去噪,不产生显式 3D 表示(无 NeRF/3DGS/Mesh 输出) [Ref-2]。如果需要可被仿真器读取的 3D 资产,这条路线不够。

数学形式

$$ p(x_{t+1} | x_{t-K:t}) = \text{Transformer}_\theta(\text{latent}(x_{t-K:t})) $$

代表工作

  • Astra(Tsinghua + Kuaishou, ICLR 2026):2D 视频世界模型,带动作控制 [Ref-2]
  • Veo 3(Google, 2025-08):闭源视频生成
  • Cosmos 1.0/2.0(NVIDIA, 2025-2026):世界基础模型,带物理推理 [Ref-3]
  • Genie 2 / Genie 3(DeepMind):可交互世界生成

3.2 路线二:4D Gaussian Splatting / Dynamic NeRF

把 3DGS(2023)从静态推广到时变场景:每个高斯点的参数都是时间的函数,通过相邻帧插值重建"会动的 3D"。适合机器人"推一把螺丝刀""拧一下扳手"等带运动视频的重建。

数学形式

$$ \mathcal{G}(t) = \{g_k(t)\}_{k=1}^{N}, \quad g_k(t) = \{\mu_k(t), \Sigma_k(t), c_k(t), \alpha_k(t)\} $$

代表工作

  • 4D Gaussian Splatting(Wu et al., CVPR 2024):奠基工作 [Ref-12]
  • Dynamic 3D Gaussians(Luiten et al., 2024):6D 跟踪场 [Ref-13]
  • Deformable 3DGS(Yang et al., 2024):canonical space + deformation field
  • SC-GS(Huang et al., 2025):稀疏控制点驱动
优点:渲染逼真度极高、新视角生成快、训练无需深度真值。
缺点:
  • 不可直接用于物理仿真——百万个绒球无法参与碰撞计算
  • 必须提取网格(通常 marching cubes),会丢失精度
  • 几何不规整——表面不闭合,无法做刚体动力学

工业适用性

适合"可视化预览",不适合直接训练。除非后处理提取网格(成本高),否则不能进入仿真器。

3.3 路线三:视频→3D/4D 重建 + 物理属性反演

3.5 路线五:VLM/LLM + 专用几何 ★ 核心

这是 2026 年最具落地性的管线。本节以 VLM 介入深度谱 (0-4) 为骨架,梳理 12+ 个代表系统,并落出 OVOW + SimFoundry 双引擎的工业实施方案。

3.5.1 核心思想:VLM 做语义路由,专用模型做几何/物理

分工原则:
  1. 语义段(VLM 强项):从像素到"是什么 / 在哪 / 怎么动"——VLM 预训练见过亿级图文对,语义对齐强
  2. 几何段(专用模型强项):从"已知语义"到"3D 形状"——TRELLIS.2 / SimFoundry 在 3D 数据上专门训练过
让 VLM 做语义理解、让专用模型做几何,是当前最优分工。让 VLM 做几何生成,就像让一个翻译家去做数学证明——不是不能,是不经济。

3.5.2 VLM/LLM 介入深度谱(0-4 档)

档位VLM 角色代表系统适用场景
0. 无 VLM 纯几何/物理模型 WorldForge、Diff4Splat、PackUV、PhysDreamer、CHORD 无需语义理解的纯几何 4D 任务
1. Prompt 工程师 自动生成下游模型的 prompt/标签 Dyna3(给 SAM 3 喂标签) 替代人工打标
2. 语义路由器 ★ 决定调哪个下游工具 / 处理哪个物体 OVOW、AGILE、SimFoundry、GeniWorld、Uranus、FunREC 多物体、多流程编排(主线)
3. 物理估计器 为 3D 物体估 mass / friction / stiffness SimFoundry Pipeline B、PhysGen(GPT-4V) 资产需真机迁移用
4. 任务提议者 自动生成操作任务(BDDL/YAML)/affordance SimFoundry Pipeline C、URDF-Anything、VLAff 数据扩增
关键洞察:档位不是"越深越好"。OVOW 用第 2 档就做到 82.7% 物理稳定性,说明"语义路由"位置介入就够用。SimFoundry 做到第 3-4 档是为了数据扩增,几何本身不需要。PhysGen 用第 3 档解决"图像生成视频的物理合理性"。选择哪一档取决于任务目标。

3.5.6 典范系统:OVOW(学术,ECCV 2026)

OVOW (One Video, One World)(arXiv:2606.31388)[Ref-20] — Tsinghua + SparcAI + USTC + PolyU + NTU + AIR Tsinghua 联合发表。首个无需训练的"单目视频 → 仿真就绪 4D mesh 场景"系统,直接输出 URDF(可被 MuJoCo / Isaac Gym / PyBullet 读取)。

  3. 渲染匹配优化:FoundationPose + RoMa v2 迭代恢复 metric scale + 6-DoF 位姿
  4. 物理装配:地面接触 + 物体互支撑 → URDF

3.5.7 典范系统:NVIDIA SimFoundry(工业,NVlabs 几何)

注意命名冲突:下文"NVIDIA SimFoundry"专指 NVIDIA GEAR Lab + Stanford 李飞飞团队 + 佐治亚理工 + UT Austin + 多伦多大学联合发布的开源 Real2Sim 系统(github.com/NVlabs/SimFoundry, arXiv:2606.28276)[Ref-26]。这与光轮智能(Lightwheel AI)的商业产品"SimFoundry / SimLayer"是两家完全不同的产品,不应混淆。

定义:SimFoundry 是模块化、自动化、端到端的 Real2Sim 流水线,从一段 RGB 视频重建出可交互数字孪生,并程序化生成"数字表亲"(digital cousins)——保 affordance 的多种变体。

阶段输入核心模块输出
A: 提取 RGB 视频 DepthAnything3 + FoundationStereo → 3D 点云 → SAM 3 分割 → VLM 打标签 → inpaint 去前景 物体 mask + 语义标签
B: 生成 实例 + 标签 Hunyuan2.1 / TRELLIS.2 → FoundationPose → VLM 估 mass/friction → PyBullet 物理稳定化 → 3DGS 背景 含物理的 OmniGibson 场景
C: 增广 数字孪生 物体 cousins(几何/外观)+ 场景 cousins(语义谓词 OnTop/RightOf 重排)+ 任务 cousins(VLM 输出 BDDL/YAML) 10²-10³ 倍扩增数据

3.5.10 §3.5 总结:选哪个?

  1. 想快速验证单物体? → 用 OVOW(开源、URDF、3.35s/帧)或 URDF-Anything(单图)
  2. 想做端到端场景 + 策略训练? → 用 NVIDIA SimFoundry(Pearson 0.911,cousins +17/+21/+40%)
  3. 想让 VLM 也估物理属性? → 升级到 SimFoundry Pipeline B / PhysGen(第 3 档)
  4. 想要 10× 数据扩增? → 启用 SimFoundry Pipeline C / URDF-Anything(第 4 档)
  5. 完全不训练? → 用 WorldForge / Diff4Splat / PackUV(第 0 档,但只能做 4D 不可仿真)
关键判断:3.5 路线在 2026 年已经收敛到 "OVOW + NVIDIA SimFoundry 双引擎" 模式——学术界做单物体 URDF,工业界做场景+策略。无需从零造轮子,直接采用 + 微调。

3.6 路线六:3D-first 视频生成(工业暂不适用)

与"2D 像素世界模型"相反:从一开始就用显式 3D 表示(3DGS、NeRF、Mesh)作为生成目标。代表系统:

  • Genie 3(DeepMind, 2025):可探索 3D 场景生成
  • UniSim(Google, 2023-2024):通用仿真器,神经渲染
  • World Labs Marble(2025):持久 3D 场景,可与 Isaac Sim 集成 [Ref-5]
  • WorldForge(Westlake University, CVPR 2026 Highlight,~2.97% 接收率)[Ref-40]
  • Diff4Splat(CVPR 2026)[Ref-41]
优点:直接产出 3D 表示、可导出。
缺点(为什么对工业资产暂不适用):
  • 长视频一致性仍是开放问题
  • 工业零件(螺丝、齿轮)的细节几何仍弱——螺丝刀头部的螺纹细节基本糊掉
  • 大多数闭源或商业 API,不可二次训练
  • 缺少物理属性标定

诚实结论:截至 2026-Q3,3D-first 视频生成不适合工业资产本体;它的工程地位类似 §3.1——适合做场景背景而非可交互零件。

  • 任务:106 个专家标注的 B-Rep 装配任务

  2. 当前商业产品都是 Copilot 模式:辅助工程师,不替代工程师
  3. 初创公司有"直接生成"能力,但仅限简单几何
  4. MUSE 基准证明即便顶级 LLM,Text-to-CAD 通过率仅 19-21%,远未工程可用
